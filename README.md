# 광주·전남 AWS 기상관측망 관리 — 1차 버전

모바일 우선 대시보드입니다. PRD의 ①~⑥ 섹션과 흐름을 구현했으며,
광주·전남 관측지점 **100개소**의 지점번호·지점명·주소·좌표가 들어 있습니다.

> ### 🚧 지금 CSV와 `index.html`이 서로 맞지 않습니다
>
> 점검일 관리를 제외하기로 하면서 CSV에서 `last_check` · `cycle_months` 칸을 삭제했지만,
> **`index.html`은 아직 두 칸을 읽는 옛 코드 그대로**입니다. 이 상태로 열면 100개 지점이
> 모두 ⚪ **"정보 확인 필요"** 로 표시됩니다.
> 아래 [상태 기능 걷어내기](#상태-기능-걷어내기-indexhtml-작업-목록)를 따라 고쳐야 합니다.

## 파일 구성

```
index.html             ← 화면 전체 (이 파일 하나가 전부입니다)
data/stations.csv      ← 지상 AWS 데이터 (엑셀로 열어서 수정)
data/marine.csv        ← 해양장비 데이터 (엑셀로 열어서 수정)
panoramas/             ← 360° 파노라마 사진 폴더
photos/                ← 해양장비 사진 폴더
vendor/leaflet/         ← 지도 라이브러리 (외부 CDN 없이 쓰려고 저장소에 포함)
tools/shrink-panoramas.py ← 파노라마 사진을 웹용 크기로 줄이는 도구
test/browser-suite.mjs ← 자동 점검 (고친 뒤 이상 없는지 확인용)
README.md
```

화면 위쪽 **`지상 AWS` / `해양장비` 탭**으로 전환합니다. 두 탭은 다루는 자료도, 출장 방식도
달라서 화면 구성이 서로 다릅니다.

## 화면 열어보기

터미널에서 이 폴더로 이동한 뒤 아래 한 줄을 실행하고, 브라우저에서 `http://localhost:8000` 으로 접속합니다.

```bash
python3 -m http.server 8000
```

> `index.html`을 그냥 더블클릭해도 열리지만, 브라우저 보안 정책상 CSV를 읽지 못해
> `index.html` 안에 넣어 둔 **내장 사본**으로 표시되고 화면 위에 안내 문구가 뜹니다.
> 내장 사본은 현재 CSV와 같은 내용이지만, **CSV를 고치면 같이 고쳐 주어야** 최신 상태가 유지됩니다.
> (`index.html`의 `FALLBACK_CSV` 부분)

## 고친 뒤 이상 없는지 확인하기

`index.html`이나 CSV를 수정했다면 아래 한 줄로 화면 전체를 자동 점검할 수 있습니다.
브라우저를 실제로 띄워 눌러 보고 **142건**을 확인합니다 (데이터 로드·검색·상태 계산·상세·파노라마·
지도 핀·경로 계산·길안내 링크·해양장비 탭·외부 의존성·실패 처리·화면 폭). 하나라도 실패하면 무엇이 어긋났는지 출력합니다.

```bash
npm install --no-save playwright   # 처음 한 번만
node test/browser-suite.mjs
```

> 시험용 서버와 데이터는 스크립트가 알아서 만들고 끝나면 지웁니다. 저장소 파일은 건드리지 않습니다.
> 경로 계산은 실제 외부 서버를 부르지 않고 **가짜 응답으로 대신**합니다. 실제 서버 연결은 별도 확인이 필요합니다.

## 화면 사용법

- **지도** — 처음에는 핀이 하나도 없습니다. 100개를 모두 찍으면 화면이 가려지기 때문입니다.
  - 목록이나 경로에서 장비를 누르면 그 자리에 **큰 남색 핀**이 뜹니다.
  - `＋ 담기`로 고른 **출장지는 파란 핀**, 출장지가 하나라도 있으면 **사무실도 남색 핀**으로 함께 보입니다.
  - 핀에는 글씨가 없습니다. 눌러 보면 지점명이 말풍선으로 뜨고 상세 카드가 열립니다.
  - `전체 보기`는 지금 떠 있는 핀에 맞춰 화면을 조정하고, 핀이 없으면 광주·전남 전체를 보여줍니다.
- **검색** — 검색창 아래 버튼으로 방식을 고릅니다.
  - `전체 검색` : 지점명·주소·번호를 모두 찾습니다 (기본)
  - `주소 검색` : 주소만 찾습니다
  - `관측장비번호` : 지점번호만 찾습니다
  - 검색어를 입력하면 접혀 있던 목록이 자동으로 펼쳐집니다.
- **관측장비 목록** — 기본은 **접힌 상태**입니다. 제목 줄을 누르면 펼쳐집니다.
- **상세** — 핀이나 목록 항목을 누르면 아래에서 카드가 올라오고, 지도도 해당 장비 위치로 이동합니다.
- **하루 출장 경로** — 목록을 펼쳐 `＋ 담기`로 장비를 고른 뒤 계산합니다.
  - 사무실에서 출발해 모든 장비를 돌고 사무실로 복귀하는 **최단 순서**를 찾습니다.
  - 맨 위에 **총 이동거리**와 **총 소요시간**을 함께 보여줍니다.
  - 거리·소요시간은 **도로 기준**입니다. 도로 값을 못 받은 구간은 직선거리와
    평균 시속(기본 60km)으로 계산하고 **`예상`**으로 구분해 표시합니다.
  - 각 구간에 `사무실 → 목포`처럼 **출발지와 도착지가 표시**되고, 그 줄의 `길안내`는
    **직전 방문지를 출발지로 고정**해서 네이버지도를 엽니다.
  - 방문지 이름(`현황 보기`)을 누르면 그 장비의 상세 카드가 열립니다.

## 해양장비 탭

지상 AWS와 다른 점만 적습니다.

- **지도·목록·검색·상세**는 지상과 같은 방식입니다. 검색의 `주소 검색` 자리가 **`해역 · 항구`** 로 바뀝니다.
- **종류 필터**가 하나 더 있습니다 — 해양기상부이 / 등표관측장비 / 파고부이·파랑계 / 연안·항만.
  CSV에 실제로 들어 있는 종류만 버튼으로 나옵니다.
- **출항 계획** — 지상의 `하루 출장 경로` 자리입니다. 담은 장비를 **출항 항구별로 묶습니다.**
  - 사무실 → 항구는 **도로 기준**, 항구 → 장비는 **CSV의 항해 시간**(`boat_min`)입니다.
  - 같은 항구에서 나가는 장비는 한 묶음입니다. 배를 하루 한 번 띄우는 것을 기준으로 했습니다.
  - **육상 접근** 장비는 각각 따로 묶입니다. 서로 다른 곳으로 차를 몰고 가야 하기 때문입니다.
  - **업체 점검** 장비는 일정에서 빼고 아래에 따로 알려줍니다.
  - 총 소요시간은 **육상 왕복 + 항해 왕복**입니다. **점검 작업 시간과 대기 시간은 빠져 있습니다.**
- **출항 전 확인** — 담은 장비 중 가장 까다로운 파고 조건을 보여주고 해상 예보로 연결합니다.
  선박으로 나가는 장비만 셈에 넣습니다.
- **상세 카드**에는 접근 방식·출항 항구·항해 시간·파고 조건·유지보수 업체가 함께 나옵니다.
  길안내는 육상 접근이면 장비까지, 선박이면 **출항 항구까지** 안내합니다.

`data/stations.csv`를 엑셀에서 열어 수정한 뒤 **UTF-8 CSV로 저장**하면 됩니다.
현재 **광주·전남 100개 지점**이 지점번호 오름차순으로 들어 있습니다.

| 칸 | 뜻 | 필수 |
|---|---|---|
| `station_id` | 지점번호(관측장비번호) | ✅ |
| `name` | 지점명 | ✅ |
| `lat` / `lon` | 위도 / 경도 | ✅ |
| `address` | 주소 | ✅ |
| `panorama` | 파노라마 파일명 (없으면 빈칸) | — |
| `note` | 비고 | — |

### 입력할 때 주의할 점

- **헤더(첫 줄) 이름은 위 영문 그대로** 씁니다. 칸 순서는 바뀌어도 되고, 필요 없는 칸을 뒤에 더 붙여도 무시됩니다.
- **좌표는 십진도만** 됩니다. `34°49'` 같은 도분초 표기는 인식하지 못하고, 그 지점은 지도 핀·길안내·경로 담기가 모두 비활성화됩니다.
- 주소나 비고에 **쉼표가 들어가면 큰따옴표로** 감쌉니다. (예: `776,현산,…,"전라남도 해남군 현산면 일평리 529-7, 529-6",776.jpg,`)
- `station_id`와 `name`이 **둘 다 비면 그 줄은 통째로 무시**됩니다.

> **점검일·점검 주기는 관리하지 않습니다.** 점검 이력은 별도 업무 체계에서 관리하고 있어 이중으로
> 들고 있지 않기로 했습니다(2026-07-30). `last_check` · `cycle_months` 칸과 상태 자동 판정
> (정상 / 곧 도래 / 점검필요)을 함께 제외했습니다. 현장에서 챙길 사항은 `note` 칸에 적습니다.

## 파노라마 사진 추가하기

**사진은 저장소가 아니라 기상청 웹서버에 둡니다.**

```
https://www.kma.go.kr/gwangju/panoramas/165.jpg
                                        └ 지점번호.jpg
```

1. 360° 파노라마(equirectangular) 사진을 준비합니다. **가로:세로 = 2:1**이어야 제대로 펼쳐집니다.
2. **웹용으로 줄입니다** (아래 참고). 원본 그대로는 너무 큽니다.
3. 파일 이름을 **`지점번호.jpg`** 로 맞춰 기상청 서버의 `gwangju/panoramas/` 에 올립니다.
4. CSV는 손대지 않아도 됩니다 — 100개 지점 모두 `지점번호.jpg`로 채워져 있습니다.

아직 안 올린 지점은 `아직 등록된 사진이 없습니다`로 표시됩니다. 오류가 아니라 정상 상태입니다.

**사진을 다른 곳으로 옮기면** `index.html`의 `CONFIG.panoDir` 한 줄만 바꾸면 됩니다.

```js
panoDir: 'https://www.kma.go.kr/gwangju/panoramas/',   // 기상청 서버
panoDir: 'panoramas/',                                 // 저장소 안 폴더로 되돌릴 때
```

특정 지점만 다른 곳에 두려면 CSV의 `panorama` 칸에 **전체 주소**를 적으면 그 주소가 우선합니다.

> `panoramas/156.svg`는 동작 확인용 샘플 그림입니다. 지금은 쓰이지 않지만,
> 저장소 안 폴더 방식으로 되돌릴 때를 대비해 남겨 두었습니다.

### 용량을 반드시 줄이세요

**GitHub Pages는 게시 사이트 용량이 1GB로 제한됩니다.** 360° 원본은 장당 3~8MB라
100개소면 그대로 한도를 넘깁니다. 저장소도 무거워져 clone이 느려집니다.

포함된 도구로 한 번에 줄일 수 있습니다. **원본은 건드리지 않고 결과만 따로 저장합니다.**

```bash
pip install pillow
python3 tools/shrink-panoramas.py <원본폴더> panoramas
```

| 가로 폭 | 장당 용량 | 쓰임 |
|---|---|---|
| 4096px | 3~8MB | 원본 보관용 — 저장소에 넣지 마세요 |
| **2048px** | **0.6~1.2MB** | **휴대폰에서 보기 충분 (기본값)** |
| 1600px | 0.4~0.8MB | 더 가볍게. 화질 차이가 보이기 시작합니다 |

2048px 기준 100개소면 **60~120MB** 정도로, 저장소에 넣어도 괜찮은 크기입니다.
파일 이름이 지점번호가 아니면 `--rename` 으로 바꿔 저장할 수 있습니다.

```bash
# '파일명,지점번호' 두 칸짜리 CSV를 주면 지점번호.jpg 로 저장합니다
python3 tools/shrink-panoramas.py 원본폴더 panoramas --rename 이름표.csv
```

> ⚠️ 사진이 기상청 서버에 있어도 이 화면 자체는 **공개 사이트**에서 열립니다.
> 공개해도 되는 자료인지 확인하세요.

## ⚠️ 운영 전 반드시 확인할 것

**1. `index.html`이 아직 옛 코드입니다.** CSV에서 `last_check`·`cycle_months` 칸을 지웠지만
`index.html`은 여전히 두 칸을 읽습니다. 이 상태로 열면 **100개 지점이 모두 ⚪ 정보 확인 필요**로 표시됩니다.
아래 [상태 기능 걷어내기](#상태-기능-걷어내기-indexhtml-작업-목록)를 따라 고쳐야 정상 동작합니다.

**2. 사무실 위치** — `index.html` 안의 `CONFIG`. 지금은 **광주지방기상청**으로 넣어 두었습니다.
실제 출발 사무실이 다르면 **이름·주소·좌표를 함께** 바꿔 주세요. 주소는 길안내 검색어로도 쓰이므로
좌표와 같은 곳을 가리켜야 합니다.

```js
const CONFIG = {
  office: {
    name: '광주지방기상청',
    address: '광주광역시 북구 서암대로 71',   // 길안내 검색어로도 쓰입니다
    lat: 35.17294, lon: 126.89156
  },
  maxPick: 8,     // 한 번에 담을 수 있는 장비 수
  ...
};
```

**3. 담당 부서 · 연락처** — `index.html` 아래쪽 `<footer>`, 지금은 "(예시)"로 표시돼 있습니다.

**4. 도로 거리 계산에 외부 접속이 필요합니다.** `CONFIG.routing`:

```js
navProvider: 'naver',                            // 길안내 버튼이 열 지도앱 ('naver' 또는 'kakao')
routing: {
  provider: 'osrm',                              // 'osrm' = 도로 기준 / 'straight' = 직선만
  osrmBase: 'https://router.project-osrm.org',   // 공개 시험 서버
  timeoutMs: 12000,
  avgKmh: 60                                     // 도로 시간을 못 받은 구간의 '예상' 시간 계산용
}
```

기본값은 OSRM **공개 시험 서버**입니다. 키가 필요 없어 바로 쓸 수 있지만 **업무용 상시 사용에는 적합하지
않습니다**(가용성 보장 없음, 과다 호출 제한). 실제 운영에서는 둘 중 하나를 권합니다.

- 기관 내부에 OSRM 서버를 세우고 `osrmBase`를 그 주소로 변경
- 카카오모빌리티·네이버 길찾기 API로 교체 — 다만 이들 REST API는 **브라우저에서 직접 호출하면 CORS로
  막히므로** 중계할 서버가 따로 있어야 합니다. 교체 지점은 `roadMatrix` 함수 하나입니다.

사내망에서 외부가 막혀 있으면 `provider: 'straight'`로 두세요. 그대로 두어도 호출 실패 시 자동으로
직선거리로 내려가고 화면에 그 사실이 표시되지만, 매번 12초씩 기다리게 됩니다.

## 알아두실 점

- **경로 거리·시간은 도로 기준**이지만 **실시간 교통 상황은 반영되지 않습니다.** 출발 전 길안내로 다시 확인하세요.
- **흑산도·가거도처럼 도로가 닿지 않는 섬**은 도로 경로가 나오지 않습니다. 이때는 그 구간만 직선거리로
  표시하고 `도로 경로를 찾지 못했습니다`라고 알려줍니다. **선박 시간표는 별도로 확인하셔야 합니다.**
- **길안내 버튼**은 **네이버지도**로 연결됩니다. 경로의 구간별 버튼은 `출발지→도착지`가 모두 지정되고,
  상세 카드의 버튼은 `현위치 출발`입니다.
  - 네이버지도는 **위경도를 그대로 받아** 검색 과정이 없습니다. 주소가 조금 부정확해도
    CSV의 좌표대로 정확히 열립니다.
  - `CONFIG.navProvider`를 `'kakao'`로 바꾸면 카카오맵으로 열 수 있지만, 카카오맵은 출발·도착
    좌표를 함께 넘기는 공개 형식이 없어 **주소 검색**에 의존하고 도착지를 무시하는 경우가 있습니다.
    이때는 CSV의 `address` 칸이 정확해야 합니다.
  - 다른 지도앱을 쓰려면 `index.html`의 `NAV_LINK`(구간별)와 `NAV_TO`(상세 카드)에 한 줄씩 추가하세요.
- **밖으로 나가는 요청은 아래 셋뿐입니다.** 사내 웹서버에 올릴 때 참고하세요.

  | 대상 | 무엇 | 막히면 |
  |---|---|---|
  | `tile.openstreetmap.org` | 지도 배경 그림 | 지도만 빈 화면. 목록·경로·상세는 정상 |
  | `router.project-osrm.org` | 도로 거리·시간 | 직선거리로 자동 전환 + 화면에 사유 표시 |
  | `map.naver.com` | 길안내 **링크** | — 서버가 부르는 게 아니라 **사용자 브라우저가 새 탭으로 여는 것**이라 서버 정책과 무관합니다 |

  지도 라이브러리(Leaflet)는 `vendor/leaflet/`에 넣어 두어 **외부 CDN을 부르지 않습니다.**
  배경 타일은 `CONFIG.tileUrl`을 기관 내부 타일 서버로 바꾸면 완전히 내부에서만 돌 수 있습니다.
  도로 거리 계산이 필요 없으면 `CONFIG.routing.provider`를 `'straight'`로 두세요.
  이렇게 하면 **외부 요청이 하나도 없는 상태**가 됩니다.
- **위치 기능과 지도는 HTTPS에서만** 정상 동작합니다. 배포 시 확인이 필요합니다.
