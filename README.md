# 광주·전남 AWS 기상관측망 관리 — 1차 버전

모바일 우선 대시보드입니다. PRD의 ①~⑥ 섹션과 흐름을 구현했으며,
광주·전남 관측지점 **100개소**의 지점번호·지점명·주소·좌표가 들어 있습니다.
(점검일·점검주기는 아직 비어 있습니다 — 아래 `⚠️ 운영 전 반드시 확인할 것` 참고)

## 파일 구성

```
index.html          ← 화면 전체 (이 파일 하나가 전부입니다)
data/stations.csv   ← 장비 데이터 (엑셀로 열어서 수정)
panoramas/          ← 360° 파노라마 사진 폴더
README.md
```

## 화면 열어보기

터미널에서 이 폴더로 이동한 뒤 아래 한 줄을 실행하고, 브라우저에서 `http://localhost:8000` 으로 접속합니다.

```bash
python3 -m http.server 8000
```

> `index.html`을 그냥 더블클릭해도 열리지만, 브라우저 보안 정책상 CSV를 읽지 못해
> `index.html` 안에 넣어 둔 **내장 사본**으로 표시되고 화면 위에 안내 문구가 뜹니다.
> 내장 사본은 현재 CSV와 같은 내용이지만, **CSV를 고치면 같이 고쳐 주어야** 최신 상태가 유지됩니다.
> (`index.html`의 `FALLBACK_CSV` 부분)

## 화면 사용법

- **지도** — 핀 색과 글자(정/곧/!)로 상태를 구분합니다. 확대·축소 후 `전체 보기`를 누르면 처음 범위로 돌아갑니다.
- **검색** — 검색창 아래 버튼으로 방식을 고릅니다.
  - `전체 검색` : 지점명·주소·번호를 모두 찾습니다 (기본)
  - `주소 검색` : 주소만 찾습니다
  - `관측장비번호` : 지점번호만 찾습니다
  - 검색어를 입력하면 접혀 있던 목록이 자동으로 펼쳐집니다.
- **관측장비 목록** — 기본은 **접힌 상태**입니다. 제목 줄을 누르면 펼쳐집니다.
- **상세** — 핀이나 목록 항목을 누르면 아래에서 카드가 올라오고, 지도도 해당 장비 위치로 이동합니다.
- **하루 출장 경로** — 목록을 펼쳐 `＋ 담기`로 장비를 고른 뒤 계산합니다.
  - 사무실에서 출발해 모든 장비를 돌고 사무실로 복귀하는 **최단 순서**를 찾습니다.
  - 거리·소요시간은 **도로 기준**입니다.
  - 각 구간에 `사무실 → 목포`처럼 **출발지와 도착지가 표시**되고, 그 줄의 `길안내`는
    **직전 방문지를 출발지로 고정**해서 카카오맵을 엽니다.
  - 방문지 이름(`현황 보기`)을 누르면 그 장비의 상세 카드가 열립니다.

## 장비 데이터 수정하기

`data/stations.csv`를 엑셀에서 열어 수정한 뒤 **UTF-8 CSV로 저장**하면 됩니다.
현재 **광주·전남 100개 지점**이 지점번호 오름차순으로 들어 있습니다.

| 칸 | 뜻 | 필수 |
|---|---|---|
| `station_id` | 지점번호(관측장비번호) | ✅ |
| `name` | 지점명 | ✅ |
| `lat` / `lon` | 위도 / 경도 | ✅ |
| `address` | 주소 | ✅ |
| `last_check` | 마지막 점검일 `YYYY-MM-DD` | ✅ |
| `cycle_months` | 점검 주기(개월) | ✅ |
| `panorama` | 파노라마 파일명 (없으면 빈칸) | — |
| `note` | 비고 | — |

### 상태는 자동으로 계산됩니다

`마지막 점검일 + 점검 주기` = **다음 점검 예정일**

- 예정일이 지남 → 🟠 **점검필요**
- 30일 이내 → 🟡 **곧 도래**
- 그 외 → 🟢 **정상**
- 날짜·주기 칸이 비었거나 형식이 틀림 → ⚪ **정보 확인 필요** (나머지 장비는 정상 표시)

## 파노라마 사진 추가하기

1. 360° 파노라마(equirectangular) 사진을 준비합니다.
   **가로:세로 = 2:1, JPG, 가로 4096px 이상** 권장
2. `panoramas/` 폴더에 넣습니다. (예: `165.jpg`)
3. CSV의 `panorama` 칸에 파일명을 적습니다. (예: `165.jpg`)

> 현재 `panoramas/156.svg`는 동작 확인용 **샘플 그림**입니다. 실제 촬영본으로 교체하세요.

## ⚠️ 운영 전 반드시 확인할 것

**1. 점검일·점검주기가 비어 있습니다.** CSV의 지점번호·지점명·주소·좌표는 실제 지점표(100개 지점)로 채워져
있지만, `last_check`·`cycle_months` 두 칸은 **비어 있어 모든 지점이 ⚪ 정보 확인 필요로 표시**됩니다.
점검 이력을 채워 넣어야 🟢/🟡/🟠 상태 구분과 `하루 출장 경로`의 우선순위가 의미를 갖습니다.

**2. 사무실 좌표** — `index.html` 안의 `CONFIG`:

```js
const CONFIG = {
  office: { name: '사무실(임시)', lat: 35.1595, lon: 126.8526 },  // ⚠️ 실제 사무실 좌표
  maxPick: 8,     // 한 번에 담을 수 있는 장비 수
  soonDays: 30,   // '곧 도래' 기준 일수
  ...
};
```

**3. 담당 부서 · 연락처** — `index.html` 아래쪽 `<footer>`, 지금은 "(예시)"로 표시돼 있습니다.

**4. 도로 거리 계산에 외부 접속이 필요합니다.** `CONFIG.routing`:

```js
routing: {
  provider: 'osrm',                              // 'osrm' = 도로 기준 / 'straight' = 직선만
  osrmBase: 'https://router.project-osrm.org',   // 공개 시험 서버
  timeoutMs: 12000
}
```

기본값은 OSRM **공개 시험 서버**입니다. 키가 필요 없어 바로 쓸 수 있지만 **업무용 상시 사용에는 적합하지
않습니다**(가용성 보장 없음, 과다 호출 제한). 실제 운영에서는 둘 중 하나를 권합니다.

- 기관 내부에 OSRM 서버를 세우고 `osrmBase`를 그 주소로 변경
- 카카오모빌리티·네이버 길찾기 API로 교체 — 다만 이들 REST API는 **브라우저에서 직접 호출하면 CORS로
  막히므로** 중계할 서버가 따로 있어야 합니다. 교체 지점은 `roadMatrix` 함수 하나입니다.

사내망에서 외부가 막혀 있으면 `provider: 'straight'`로 두세요. 그대로 두어도 호출 실패 시 자동으로
직선거리로 내려가고 화면에 그 사실이 표시되지만, 매번 12초씩 기다리게 됩니다.

## 알아두실 점

- **경로 거리·시간은 도로 기준**이지만 **실시간 교통 상황은 반영되지 않습니다.** 출발 전 길안내로 다시 확인하세요.
- **흑산도·가거도처럼 도로가 닿지 않는 섬**은 도로 경로가 나오지 않습니다. 이때는 그 구간만 직선거리로
  표시하고 `도로 경로를 찾지 못했습니다`라고 알려줍니다. **선박 시간표는 별도로 확인하셔야 합니다.**
- **길안내 버튼**은 카카오맵으로 연결됩니다. 경로의 구간별 버튼은 `출발지→도착지`가 모두 지정되고,
  상세 카드의 버튼은 `현위치 출발`입니다. 다른 지도앱으로 바꾸려면 `index.html`의 `navLink` 함수와
  `openSheet` 함수 안 `navUrl` 부분을 수정하세요.
- **지도(Leaflet)는 인터넷 연결이 필요**합니다. 사내망처럼 외부 접속이 막힌 환경이라면 지도만 표시되지 않고, 목록·경로·파노라마는 정상 동작합니다.
- **위치 기능과 지도는 HTTPS에서만** 정상 동작합니다. 배포 시 확인이 필요합니다.
